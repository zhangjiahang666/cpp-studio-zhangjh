九大功能，覆盖本地评测全流程

从写完代码到确认正确，中间的所有步骤都在一个窗口里完成。

单题评测

一个源码 + 一个数据目录，一键列出每组 AC / WA / TLE / 无输出、得分、用时、期望与实际输出。

多题评测

一次添加多道题批量跑，结果按题分组汇总；单题出错不中断后续，最后统一出总分。

对拍找 bug

主程序 vs 暴力/标程，随机数据逐轮比对；遇到分歧不中断，跑完全部轮一次性列出所有问题组。

造数据

用自己写的生成器批量产出 .in 与 .out，想控数据内容时用它。

随机数据

不会写生成器？填输入格式、范围、数量即可；附 AC 代码则顺带跑出 .out，留空只出 .in。

评测记录

单题 / 多题 / 对拍 / 造数据每次运行自动保存，软件内可回看历史，内置改动日志。

多编程语言

C++ / Python / Java 一键切换：g++ 编译、解释器直跑、javac + java 编译运行，选「浏览」时按扩展名自动识别。单题、多题、对拍、造数据全流程通用。

两种写法，都支持

不管你的题解是文件读写还是标准输入输出，直接丢进来就能测。

freopen 文件读写 传统 OJ 写法

程序用 freopen 读写固定文件名，评测时把每组数据复制为 <题名>.in，跑完拿写出的 <题名>.out 与期望比对。

freopen("calendar.in", "r", stdin);
freopen("calendar.out", "w", stdout);

cin / cout 标准输入输出 洛谷 / tarjano 写法

程序从 stdin 读、往 stdout 写。评测时自动把该组 .in 喂给程序，再捕获标准输出与期望比对。

cin >> n;
cout << ans << "\n";

两种写法同时存在时，优先采用程序写出的 <题名>.out；数据目录放 *.in 与同名 .out（优先）/ .ans 期望输出。

常见问题

结果显示「无输出」怎么办？
确认程序确实有产出：freopen 写法请检查输出文件名是 <题名>.out（与源码同名）；cin/cout 写法会被自动捕获。两者都没输出时才会判「无输出」。
结果显示「CE」？
编译失败，结果里会带上 g++ 的原始报错信息，按提示改源码即可。默认标准为 C++14，可在界面调整。
提示找不到编译器？
在界面「编译器」一栏填你本机 g++ 的完整路径，例如 C:\mingw64\bin\g++.exe，保存后长期生效。若本机还没有 g++，先下载 MinGW-w64 环境 并解压到 C:\mingw64。
评测会弄脏我的数据目录吗？
不会。评测临时文件（<题名>.in / <题名>.out）只产生在数据目录内，每次评测结束自动清理，不影响原始数据。
macOS / Linux 能用吗？
可以，用源码版：下载源码包后，需要本机 Python 3 和 C++ 编译器，运行 python3 ojjudge.py，并在界面把编译器路径改成 clang++（macOS）或 g++（Linux）。注意 Python 必须自带 tkinter（python.org 官方版有；报 No module named 'tkinter' 就换官方版，或用 exe）。完整步骤见使用说明 · macOS/Linux 源码版。
对拍时三个程序都要用标准输入输出吗？
是。生成器写 stdout，主程序与暴力/标程读 stdin 写 stdout。如果原程序用了 freopen 固定文件名，请先改成标准输入输出再对拍。
